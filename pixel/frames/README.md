# pixel/frames — 部件搬运造出来的帧（**提案**，还没进图集）

路线来源：2026-11-01 拉 Codex 做的第二意见 —— 结论是"**原像素复用 + 整数位移 + 手绘补缝**"优先，
AI 逐帧重画最后；理由与我们自己的实测一致（损伤发生在 448px 重画那一步，后处理补不回来）。

工具：`tools/frame-parts.py`。铁律：**输出像素必须是输入像素的副本**（颜色只来自输入，不重采样、
不重量化），否则抖动纹理会被打散。

## 通过：`idle-breathe/`（4 帧循环）

```bash
python3 tools/frame-parts.py --op breathe --base pixel/art/<col0 切出的帧>.png \
  --band 60:96 --offsets 0,-1,0,1 --name idle_breathe --out-dir pixel/frames/idle-breathe
node tools/frame-gate.mjs --base <col0> --cand pixel/frames/idle-breathe/idle_breathe_1.png --allow 60:96
```

四帧全部过门禁，关键那条是 **`outsideRegion = 0`**：动作带（y≥60）之外的像素**一个都没动**。
其中第 0/2 帧与基准逐像素相同 —— 循环的休息帧本来如此，用 `--allow-identical` 表达（Codex 也明确
"允许重复帧和不等时长，别强求六张独特图"）。

⚠️ 但这套帧的**净收益有限**：呼吸本来已经由 CSS 的 `av-breathe` 做了；真正的缺口是"更多**不同姿势**"。

## 被否：`_sheet-idle-blink-rejected-2026-11-01.png`（眨眼自动合成）

想法：两张源帧的**差异包围盒**就是眼睛区域，把包围盒下半部取自闭眼帧 ⇒ 半闭帧。
实测：差异包围盒是 **[1,10,95,86]≈整张图**（这套素材的两帧在全身都有细微差异），于是"半闭"帧实际
变成"上半身睁眼 + 下半身闭眼"的横向拼接，脸上一道灰带（见被否的图）。

结论：**差异框自动定位眼睛在这套素材上不成立**；要做眨眼必须**显式给眼睛框**（需人工标注一次），
`frame-parts.py --op blink` 保留了这个能力，但需要 `--box` 参数（尚未加，等有人愿意标一次）。

## 通过：`sleep-z/`（4 帧，Zz 浮动）—— **观感上真的能用**

`tools/frame-parts.py --op shift --base <sleep col0> --box 70,8,90,46 --offsets 0,-1,0,1`

Zz 符号整体上下整数位移，身体一个像素都没动。肉眼可见 Zz 在浮动（见 `_sheet-sleep-z-2026-11-01.png`），
这正是睡眠状态缺的那种"活的痕迹"。四帧全过门禁（`outsideRegion = 0`）。

## 通过但收益小：`busy-type/`（4 帧，笔记本 1px 上下）

`--box 20,62,62,86 --offsets 0,1,0,-1`。门禁全过，但 1px 位移在 48 CSS px 下**几乎看不出来**，
而且笔记本上沿贴着深色身体，接缝不可见也意味着"没有可读的动作"。**结论：这类不动轮廓的小物件位移
只适合做"有独立轮廓、且视觉占比够大"的部件（Zz 就是），不适合笔记本。**

## ⚠️ 合成被一个**既有缺陷**挡住：whale-maid 图集每格底部带残片

2026-11-01 第一次跑 `compose-atlas.mjs` 时发现：`whale-maid-sheet.atlas.png` 的**每一格底部都压着
一条相邻行的碎片**（在 preview 图上就是每个角色脚下那道"被压扁的横条"）。实测各格内部的空带：

| 行 | 格内空带 y 区间 | 含义 |
|---|---|---|
| idle | [0,6] | 底部**没有**空带 ⇒ 残片和角色连在一起 |
| busy | 无 | 同上 |
| alert | [86,87] | 88 以下就是残片 |
| happy | [6,8] [87,89] | 90 以下是残片 |
| unknown | [9,10] [85,95] | 干净（底部是空的） |

根因：whale 的源图行与行之间**没有整行空白**（当初就是用 `--grid content` 切的），行带被算得偏高，
crop 把下一行的一截带了进来。

顺带修掉一个真 bug：`slice-sprite-sheet.py` 的 `gaps` 模式失败时**只返回两个值**，而调用方按三元组
解包 ⇒ 失败路径变成 `ValueError` 崩栈，真正的错误信息（"没找到 6 行"）看不到。已修（返回 `None, msg, None`，
现在能正确打印 `gaps 模式没找到 6 行（得到 1）`）。

**已修（2026-11-01）**：新增 `tools/trim-atlas.py` —— 逐格统计上下 16 行里不透明像素数的**低谷**当切点，
把切点以外的行清空（残片比角色窄，所以低谷一定落在残片顶上）。逐格判定，不共用同一行的切点
（实测 alert 左右两格残片高度不同）。whale 的切点：底部 85–87、顶部 6–12。
修完再 `compose-atlas`，两套图集都变成 **384×576（4 列）**，`sleep` 四帧 `[850,850,850,850]`。
残留：alert 左格左上仍有 1 小块橙色碎片（上一行"!"的残角，与角色同 y 不同 x，行向切点切不掉），
要彻底清得加"贴边连通域"规则——目前可接受。
